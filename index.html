01 / INTRODUCTION

项目简介

拆解组件库规范并结构化沉淀，建立组件与业务场景映射关系，参与 AI Skill Prompt 与规则体系建设，将设计系统规范转化为 AI 可执行规则。

01

规范结构化沉淀

拆解大众点评组件库规范，将散落在 Figma / Sketch 中的设计系统——色彩、字号、圆角、间距、组件状态——结构化沉淀为 AI 可检索的规范文档。

02

检索策略设计

参与 AI Skill Prompt 与规则体系建设，设计按需检索路由策略，让 AI 按需查规范而非全量硬灌，从 20 万 Token 压缩至 1.5 万 Token。

03

核心目的

针对 AI 生码过程中设计还原度不稳定、组件使用不统一的问题，构建大众点评 Design Coding Skill，让规范从"给人看的画布"进化为"给 AI 用的接口"。

02 / PAIN POINTS

背景与痛点

当 AI Coding 遇上"大厂设计规范"——Cursor / Claude 等工具让前端转代码效率提升 3 倍，但大众点评业务中，AI 生成代码的设计还原度不足 40%。

🟠

规范失效

AI 生成的尺寸间距随心所欲，与点评 Design System 严重偏离。色彩、字号、圆角等视觉参数缺乏统一约束，AI 靠"经验补全"和"审美优化"产出代码，无法追溯参数来源。

🟠

组件复用断裂

团队已有成熟的代码组件（如瓷片区、货架模块、评价卡片等），AI 却总是"重新造轮子"，从零手写 CSS/HTML 模拟，效率低且难以覆盖全部交互状态。

🟠

设计系统"不可读"

传统 Figma / Sketch 规范是写给设计师看的，AI 直接加载导致 Token 爆炸（20 万+）且检索混乱。设计系统从来没有被设计成"AI 可读"的形态。

CORE INSIGHT · 核心诉求思考

表面看是三个孤立的技术问题，实际上指向同一个底层命题：我们的设计系统，从来没被设计成"AI 可读"的形态。

所以，我们要做的不是教 AI 学设计，而是把设计语言重新"编译"成 AI 能高效检索和执行的结构化协议。让规范从"给人看的画布"，进化为"给 AI 用的接口"。

03 / SOLUTION

核心策略与解决方案

总目标：构建一套设计系统与 AI 之间可执行的桥梁，最终输出可跑在移动端界面运行的 HTML 前端代码。以"商户详情页"为例，分三步落地。

✦

核心策略

现状：传统设计系统（全量规范）➡️ AI 无法解读（过长、非结构化、不可检索）
解法：AI 可读化改造（代码组件 / 模块布局 / 视觉 Token）➡️ 智能路由引擎 ➡️ 高质量代码生成
1

意图解析——是否已有现成代码组件？

编写 INDEX.md + component-mapping.md，将大众点评组件与自然语言触发词绑定。AI 接收用户需求后，先查索引判断是否命中已有代码组件，命中则直接复用，杜绝重复造轮子。
商户信息页结构映射示例：
① 顶部导航（Subpage Navigation）← 状态栏 + 返回导航 + 页面标题
② 选项 Tab 栏 ← 锚点导航（sticky 吸顶）
③ 营业时间 ← 特殊原子：时间图片 + 反馈行
④ 商户事迹 ← 特殊原子：收录标签 + 时间线 + 图片
⑤ 店铺特色 ← 特殊原子：标题 + 描述 + 3 图 + 反馈行
⑥ 服务设施 ← 特殊原子：设施 / 服务 / 环境三分类
⑦ 其他分店（可选）← 特殊原子：入口行
⑧ 食品安全档案 ← 特殊原子：入口行
⑨ 悬浮条（底部 Home Indicator）← 固定底部，iOS 安全区域
成效：命中 scenario: 页面服务-商户信息页.md，组件命中率提升 70%
2

模块路由——模块内部怎么排版？

编写 module-商户信息卡.md，定义数据信息（名称 / 评分等）的布局优先级与分层逻辑。让 AI 理解"信息结构"，而非排版。以商户详情页为例，页面由上至下的模块编排如下：
↓ 头图区（顶部封面 / 轮播）
↓ 商户信息卡（评分 / 地址 / 营业时间 / 优惠券横条）
↓ 货架模块 · 到店套餐（GoodsShelfGroupon）
↓ 货架模块 · 超值券（GoodsShelfCoupon）
↓ 货架模块（评价区标题 + 评价列表）
↳ 每项 → 评价卡片（含 AISummaryCard / QuesAndAnswer）
↓ 底部操作栏（收藏 / 写评价 / 分享）或价格交易卡（锁定条）
3

组件视觉 Token——细节长什么样？

编写 scenario-商户信息页.md，将色彩、圆角、间距固化为精确数值，让 AI 精准应用视觉规范。通过建立"颜色色板"、"圆角体系"、"间距体系"及链路规则，AI 检索能力提升，彻底消除"凭感觉"的视觉偏差。
体系 元素 Token 值 说明
色彩基调 页面背景 #F6F6F6 浅灰底，模块间隔区域
卡片底色 #FFFFFF 所有内容白色卡片
圆角体系 普通模块卡片 0pt 内容卡片满屏铺设，无圆角
"收录 8 年"标签 2pt 商户事迹中的收录年份标签底色圆角
边距体系 页面→卡片（外壳间距） 0pt 卡片全宽撑满，无左右外边距
卡片→内容（内边距） 20pt 左右内边距各 20pt，内容可用宽度 350pt
成效：上下文从 20 万 Token 被压缩至 1.5 万 Token，彻底消除"凭感觉"的视觉偏差
