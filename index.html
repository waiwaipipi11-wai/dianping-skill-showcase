01 / PAIN POINTS

背景痛点

AI 生码过程中，设计规范分散、组件复用率低、视觉一致性难以保障，是设计研发协作的核心瓶颈。

⚠️

规范分散，AI 无从遵循

色彩、字号、圆角、间距等视觉规范散落在多个文档中，AI 生码时缺乏统一的上下文来源，容易"经验补全"或"审美优化"，产出的代码无法追溯参数来源。

🔄

复杂组件重复手写

瓷片区、货架模块、评价卡片等复杂状态组件已有高保真代码实现，但 AI 不知道组件存在，每次都从零手写 CSS/HTML 模拟，效率低且难以覆盖全部状态。

📐

模块排版缺乏策略

同一模块（如商品卡片、店铺卡片）在不同场景下有不同布局模式和状态路由，缺乏统一的「场景→状态→布局」决策路径，导致排版不一致。

🔍

规范加载低效

一次性加载全部规范文档导致上下文爆炸，而按需加载又缺乏索引和路由机制，AI 难以快速定位到真正需要的模块和组件规范。

02 / SOLUTION

三层资产体系

三层规范配合 = AI 知道「是否该直接调代码」+「模块内部怎么排」+「每个控件视觉参数」。每一层按需加载，绝不一股脑全读。

Layer 0 · CODE 代码组件路由

管「是否已有高保真代码实现」。复杂状态组件优先复用 bundled 代码，模块文档负责场景→状态路由，代码契约负责 props / 构建 / 导出。

规范文件：references/component-source-registry.md、references/code-components/*.md
覆盖组件：瓷片区 / Tile（本地源码）、d2c-components（89 个组件，npm 按需安装）
Layer 1 · MODULE 模块布局策略

管「模块内部怎么排版 / 怎么选状态」。模块内部布局模式、信息优先级、适配差异；对代码组件型模块，负责场景→状态→代码调用路由。

规范文件：references/specs/module/module-*.md
覆盖模块：17 个模块布局策略，含瓷片区、商品卡片、店铺卡片、货架模块、评价卡片等
Layer 2 · COMPONENT 组件视觉规范

管「细节长什么样」。颜色、字号、圆角、间距、阴影、组件尺寸与状态——每个控件都有精确的视觉参数值。

规范文件：references/specs/component/component-*.md
覆盖组件：色彩、文字、容器、按钮、图片容器、标签、货币、星级、红点、浮层等

04 / EXECUTION FLOW

执行流程

从环境检查到代码生成再到评审，7 步强制流程确保每一步都有据可查、参数可追溯。

0

判断是否触发底图直出

每次调用优先执行。若用户只想获取完整页面 HTML 底图且无修改意图，走快捷路径原样输出；否则进入 Step 1。

1

检查并准备运行环境

检查 pnpm 可用性、@picasso/d2c-components 是否已安装且为最新版、样式入口是否已引入。未通过则执行修复，不得跳过。

2

判断是否命中代码组件

读取 component-source-registry.md，根据用户需求关键词判断是否命中已有代码组件。命中则优先复用，禁止手写替代。

3

按需加载模块布局策略

分析需求涉及哪些模块，查模块表只加载命中的模块规范。不确定时先读布局策略总览或高频场景索引。

4

按需加载组件视觉规范

根据功能推断涉及哪些组件的视觉细节，查 INDEX.md 推断速查表，只加载命中的组件规范，获取精确视觉参数。

5

输出视觉规范上下文文档

将 Step 2~4 命中的规范合并为结构化的「施工图纸」，具体到模块、状态、信息元素、字体、颜色、间距、圆角等参数。

6

生成代码 + 检查评审

基于上下文文档生成代码，仅可使用命中规范中明确出现的参数，禁止经验补全。生成后执行编码约束检查与视觉设计评审，输出自查报告。

05 / REUSABLE CAPABILITY

可复用的能力

Skill 将设计规范沉淀为可复用的代码资产和决策路径，支撑多业态、多场景的页面快速生成。

CODE

代码组件复用

89 个 d2c-components（列表项、筛选、导航、底部弹层、优惠券、FAB、评分等）+ 本地瓷片区 TileCard 源码，命中即调，禁止重画。

MOD

模块状态路由

每个模块提供「场景→状态→布局/代码调用」决策路径。如瓷片区根据业态选择 single_supply / multi_supply 状态，货架模块区分到店套餐与超值券变体。

VIS

视觉参数可追溯

每个颜色、字号、圆角、间距都有精确 Token 值和来源文件。生码结果可追溯，自查报告中标明关键参数的规范文件和参数项。

IDX

按需索引加载

三层按需加载机制：先确认用户诉求，再判断是否命中代码组件，只加载真正需要的模块、组件和代码契约文件，避免上下文爆炸。

CHK

强制检查与评审

生码后必须执行编码约束检查（规范执行、代码组件、可选项、图标、价格、自适应）和视觉设计评审（排版、视觉细节、一致性、手机适配）。

EXT

可扩展架构

新增模块或组件时，在 INDEX.md、component-source-registry.md 和相关 mapping 文件中补充触发词与说明即可，无需修改流程逻辑。
